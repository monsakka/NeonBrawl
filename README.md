# NEON BRAWL

A 2D platform fighter for Windows, Android and iOS. All three platforms run the same game code in `www/`.

## Folder layout

```
My game/
├─ www/                  ← THE GAME. Edit things here.
│  ├─ index.html         page layout and menus (HTML)
│  ├─ css/style.css      menu and UI styling (+ css/ui18.css, the v18 glass redesign, css/ui19.css: Mastery, PFPs, shop cards, minigame boards, and css/ui20.css: the Pro Pass)
│  ├─ fonts/             Orbitron + Inter (bundled so the game works offline; OFL licensed)
│  └─ js/
│     ├─ core/           config, shared state, math helpers
│     ├─ data/           stages, characters, moves, CPU difficulty, skins, Ultimates  ← add content here
│     ├─ audio/          procedural sound effects + the 36 stage soundtracks (no audio files)
│     ├─ game/           input (keyboard/mouse + touch + gamepad), physics, combat, hazards, fighter logic, AI, Ultimates, online play, match flow, minigames.js (Volley Brawl + party modes), bowling19.js + lava19.js (v19 minigames)
│     ├─ render/         drawing: the WebGL 2.5D renderer (gl3d, stage3d, fighter3d, fx3d, weather3d, ultfx, menu3d, maps14…), the canvas fallback, poses + motion (animation), HUD, models19.js (v19 heads + the Mastery skin), models20.js (AXO) · stage20.js (Prismatic Cathedral) · rewards20.js (Pro skins, KOs, nameplates, emojis)
│     ├─ ui/             menus.js (screens, settings, character/stage select) · training.js (Training mode) · profile.js (username + titles) · battlepass.js · shop.js (Coins + Item Shop) · platform.js (iOS / orientation) · controls18.js (key binds + touch layout) · mastery19.js (Favorite Fighter + Mastery + PFPs) · propass20.js (the 10,000-Coin Pro Pass)
│     └─ main.js         main loop and startup (loaded last)
├─ desktop/main.js       Windows app wrapper (Electron)
├─ android/              Android Studio project (generated by Capacitor)
├─ ios/                  Xcode project (generated by Capacitor)
├─ tools/smoke-test.js   automatic test: plays every stage and checks for errors
├─ tools/build-single.js bundles www/ into one self-contained HTML file
├─ single-file/          output of that bundle (generated: don't edit, rebuild instead)
└─ original/             your original single HTML file (untouched backup)
```

The scripts are plain `<script>` files that share one global scope, so **load order matters**.
If you add a new `.js` file, add a `<script>` tag for it in `www/index.html`, after the files it depends on and before `main.js`.

## Everyday commands

Run these from inside the `My game` folder:

| Command | What it does |
|---|---|
| `npm start` | Play the game in a desktop window (F11 = fullscreen) |
| `npm test` | Smoke test: plays all stages CPU vs CPU and reports any errors |
| `npm run build:single` | Builds `single-file/index.html`: the whole game (code, styles, fonts) in one file that runs offline from a double-click |
| `npm run test:single` | Rebuilds the single file and runs the smoke test on it |
| `npm run balance` | CPU-vs-CPU round robin of every fighter; prints win rates (`npm run balance -- featured 4` = just the featured 8, 4 rounds) |
| `npm run build:win` | Builds a Windows installer and a portable `.exe` into `dist/` |
| `npm run android` | Copies `www/` into the Android project and opens Android Studio |
| `npm run ios` | Same for iOS. **Needs a Mac with Xcode** |

You can also open `www/index.html` directly in a browser.

## Growing the game

- **Roster size:** the select screens show all 80 fighters (in a scrolling grid) and 36 stages. "Featured 8 only" / "Featured 6 only" (or Settings → Roster) narrows them to the headline fighters (`FEATURED_FIGHTERS` in `data/characters.js`) and stages (`FEATURED_STAGES` in `data/stages.js`). Random picks only choose from what's visible.
- **New fighter:** add an entry to `CHARS` in `www/js/data/characters.js`, a `MOTION` profile + victory / defeat animations in `render/motion.js`, and an Ultimate in `data/ultimates.js` (the smoke test fails until all exist and are unique). It automatically gets 3 skins (Classic, Gold/Neon Nitro, Shadow) from `data/skins.js`; its look-specific extras (helmets, hair, tails) go in `drawAccents` in `render/fighters.js`, and its victory stance in `VICTORY_STYLES` in `ui/menus.js`.
- **Character-select performance:** the roster tiles are a portrait cache (`renderTile` / `drawCharPreviews` in `ui/menus.js`). Each tile is drawn once at full quality and redrawn only when its skin or the graphics settings change; only the hovered fighter and the two picks animate, and only while they are scrolled into view. The first fill of the cache is spread over a few frames (`PORTRAIT_BUDGET_MS`). Roster tiles and stage cards also skip the CSS `backdrop-filter` blur, which forced the GPU to re-blur every tile every frame. Measured: 7.0 ms → 0.66 ms per frame (worst frame 18.3 → 1.8 ms).
- **Skins:** a skin only sets a fighter's colours (`f.color` / `f.fill`), and everything that glows follows them. Players pick skins on the character select by clicking their fighter again, the dots under each card, or the swatches in the detail panel. Choices are remembered.
- **New stage:** add it to `STAGES` in `www/js/data/stages.js`, plus a background function in `render/arenas.js` or `render/backgrounds.js` (registered in `BACKGROUNDS`). Backgrounds are built from parallax layers: far sky, distant scenery, mid scenery, then the stage itself. Use `cachedLayer()` (arenas.js) for anything static so it is drawn once, not every frame. Give a stage `clean: true` for the high-contrast competitive platform style.
- **Balance:** see `core/config.js` (physics), `data/moves.js` (damage and knockback) and the per-fighter patch in `data/balance.js`. `npm run balance` plays every fighter against every other and prints win rates.
- **Animation:** `render/poses.js` holds every named pose (255 of them: locomotion, every attack's wind-up / charge / strike / recovery, specials, hits, ledges, 23 victory and 4 defeat stances). Faces are drawn in `drawFace` (`render/fighters.js`): eyes glide to track the opponent, narrow with a bead of sweat while charging a smash, spin into spirals after a shield break, and beam ^^ on the victory screen. `computePose()` picks a base pose per frame, then `archetypePose()` restyles it for the fighter's body type (`arch` in `characters.js`: heavy, brute, ninja, knight, mage, float, acrobat, racer, skater, mutant, …). Each archetype has its own proportions (`RIG_BUILD`), lean and idle. `drawFighter()` blends between poses with springs, then solves elbows and knees with two-bone IK (`ik2`). To change how a move looks, edit its entry in `ATTACK_POSES`.
- **Per-fighter motion (`render/motion.js`):** every fighter has its own motion profile in `MOTION`:
  - a gait generator with its own stride, bounce, lean, cadence and arm carriage. The gaits are stomp, sprint, bounce, hover, quadruped bound, skate, slither, march, prowl, swagger, lope, wing-glide, robot, glitch, undead stagger, dance and shuffle;
  - a jump-squat depth, which sets the launch squash and stretch;
  - a mid-air style and a matching double jump: somersault, back-flip, corkscrew, wing-beat, thruster, meditation, cape-dive, superman, pounce and others;
  - screen-shake on each footfall for heavy fighters, and a sprint effect (ghost trails, sparks, embers, frost, pixels, shadow, petals).

  Every fighter also has its own keyframed victory animation (`VICTORY_ANIM`) and defeat animation (`DEFEAT_ANIM`). Some include scene props: Dino's F1 car, Pulse's turntable, solar auras, and smoke rising off broken armor. `computePose()` applies the motion layer last. The smoke test checks that all 80 profiles and all 80 victory/defeat pairs are unique.
- **3D look:** `render/shading.js` is the lighting engine. One key light comes from the upper left. Every body part gets a gradient base, ambient occlusion where parts meet, a rim light on the shadow side and a specular highlight. How shiny or matte a part looks comes from the fighter's material (`mat` in `characters.js`: metal, gloss, cloth, stone, ice, slime, energy, brass, …; recipes in `MATERIALS`). Settings → Graphics → Neon switches back to the flat neon style.
- **Cel shading (v3 "Overdrive"):** `SHADE` in `shading.js` adds a hard toon band to every gradient (`cel`) and a bold ink outline (`ink`, in px). Tank archetypes (heavy, brute, knight) get shoulder pauldrons, and smash charges squash and wobble before they stretch on release (`fighter-update.js`).
- **Menus (v3):**
  - **Title:** chrome-edged glass cards (`.mcard`), floating HUD panels, a 3D particle field and sweeping stage lights (`drawMenuBackdrop` in `backgrounds.js`).
  - **Character select:** a showcase pedestal under a volumetric spotlight with a live floor reflection and idle camera angles (`drawShowcase` in `ui/menus.js`). The fighter is drawn once into a buffer, and the reflection is that buffer mirrored and faded. There are also metallic foil class badges (`fighterClass` / `CLASSES`), real frame data read through `buildMove` (`frameData`), angled VS nameplates with live portraits (`drawPlate`) and match-parameter chips.
  - **Stage select:** isometric glass cards with hazard icons, plus an inspector panel. The inspector shows a live parallax preview, hazard and mechanic badges, and an SVG platform diagram generated from the stage data (`stageFeatures` / `layoutSVG`). Card previews are a render cache filled within `STAGE_BUDGET_MS` per frame; only the hovered card animates.
  - **Pause:** a frosted card with a keymap and a combo guide.
- **HUD (`render/hud.js`):** angled chrome plates, cached per colour with `uiLayer()` from `draw-utils.js`, so there are no per-frame blur filters. On top of each plate: live portraits, a glowing colour-shifting % counter, gem stock badges and segmented meters. Portraits are drawn in place, not into a side canvas, because blitting a canvas that was just redrawn forces a GPU sync between contexts.
- **Stage atmosphere (`render/atmosphere.js`):**
  - drifting fog bands and swaying light shafts behind the arena;
  - volumetric light spilling under the stage and platforms, plus bevelled chamfers and specular lips;
  - per-stage directional particles (embers, sparks, snow and ice mist, leaves, petals, rain, bubbles, dust, spores, data bits, shards, motes). The theme table is `ATMO`; particles are a pure function of index and time, so nothing is allocated per frame.
- **2.5D WebGL renderer (v4):** gameplay is still a strict 2D simulation (x / y, 2D hitboxes, fixed 60 Hz). Only the presentation is 3D. The renderer is native WebGL 1 with no libraries.
  - `render/gl3d.js` is the core: matrix maths, the GLSL shaders and the passes.
    - The lit shader does Blinn-Phong, a toon band, hemisphere ambient, contact AO, fresnel rim, environment reflections for metals and distance fog. Ink outlines are inverted hulls.
    - Real-time shadows come from a light's-eye depth map (RGBA-packed, 4-tap PCF).
    - The camera dollies with the follow-cam zoom and uses a lens-shifted frustum, so the gameplay plane maps exactly like the 2D camera while depth shows true perspective. The smash-cam roll is applied in clip space.
  - `render/stage3d.js` builds the stages (see v6 below for the current version).
  - `render/fighter3d.js` builds the fighters from the shared skeleton solver (`solveRig` in `render/fighters.js`), so every fighter's moves, springs and IK carry over unchanged.
    - Each fighter gets capsule limbs, sphere joints, 3D eyes, weapons, wings and tails.
    - `ACC3D` holds a per-fighter recipe of 3D signature accents.
    - Spin attacks, spinning specials and hard launches turn the model around its vertical axis.
  - `render/render3d.js` runs each frame (see v6 below).
  - Settings → Renderer switches back to the classic canvas renderer. The game also falls back to it automatically if WebGL is missing or the context is lost.
- **v5 features:**
  - **Skins as materials:** Base is cel-shaded with rim light; Gold Edition is polished metallic gold; Void is black obsidian with glowing red eyes, a red rim light and a smoke trail. They're defined in `data/skins.js` and drawn in `render/fighter3d.js`. The primitives are high-poly with smooth normals and linear-step toon shading.
  - **Star and Screen KOs (`render/kofx.js`):** a KO off the top of the screen either sends the fighter tumbling into the deep background until it twinkles as a star, or flies it at the camera to slam against the "glass" with cracks. This is presentation only; respawn timing doesn't change. Haptics (`navigator.vibrate`) fire on heavy smashes, big launches and KOs (Settings → Haptics).
  - **Time limit and Sudden Death:** set the time limit on the setup screen. A timeout with equal stocks, or a double KO, starts Sudden Death: one stock each at 300%, red emergency lighting, double-tempo music, a tighter camera and a slow-motion final blow. The code is `timeUp` / `startSuddenDeath` in `game/combat.js`.
  - **Training (`ui/training.js`):** Main menu → Training opens the Holo Training Grid (`TRAINING_STAGE`, which isn't in the stage list).
    - The dummy can stand, walk, jump, shield, attack or play as the full CPU at any level.
    - You can set the dummy's damage, reset positions, and stocks are unlimited.
    - The hitbox overlay draws the exact rectangles `tryHit` and grabs test each step (`HITBOX_LOG`), plus hurtboxes and projectiles.
  - **Online, same Wi-Fi (`game/netplay.js`):** (v12 adds room codes over the internet; see the v12 notes below)
    - **Connecting:** WebRTC data channels with no server. The host's offer and the guest's answer are swapped as compressed codes by copy, paste or share; only LAN candidates are used. These manual codes are still available under "No internet? Connect on the same Wi-Fi…" on the Online screen.
    - **Netcode:** deterministic lockstep with a 3-frame input delay. During each step `Math.random` is a shared seeded generator. Cosmetic effects use the device's own RNG so local settings can't drift the simulation, and presses that land during hit-stop carry over to the next frame that reads input.
    - **Sync safety:** state hashes are exchanged every second; on a mismatch the host sends a snapshot. In a two-window test, a full match ran at 60 fps with every checkpoint identical.
  - **Intro:** a WebGL particle tunnel (`glIntro` in `render/gl3d.js`) runs behind the splash.
- **v6: everything is cel-shaded 3D.** No in-game entity is drawn with 2D canvas calls any more; the `#game` canvas stays empty while WebGL runs. It's only used by the no-WebGL fallback renderer.
  - **Toon look (`render/gl3d.js`):** three hard light bands, a hard specular highlight and a crisp rim line. Thick black ink outlines are inverted hulls pushed out in screen space, clamped to a pixel range, and fade with the distance fog.
  - **Batching:** effects use per-frame dynamic batches (`DynBatch`). There are four: inked toon, flat toon, see-through and additive glow. Each one is a single draw call.
  - **Procedural toon sky:** gradient, stepped sun halo, a shaded moon or planet, banded cartoon clouds, stars and aurora (`stageSky`).
  - **Screen-effect pass:** vignette, flashes, the damage vignette, Sudden Death emergency beacons, blinding white-out and the menu dim layer.
  - **Stages (`render/stage3d.js`):** the painted decals and backdrops are gone. Each arena is built from 3D detailing merged into its blocks (`stageDeco`): kerbs, tatami, floorboards, columns, rivets, icicles, moss, roots, chevrons, lava cracks, crystals and more.
    - Animated details are rebuilt every frame (`stageAnim3D`): lights, scrolling lane lines, light-up floors, cogs, lanterns and anemones.
    - Built stages are cached (`STAGE_CACHE`).
  - **Effects, projectiles, abilities, hazards and props (`render/fx3d.js`):** all real geometry. This covers particles, swept 3D slash ribbons, every projectile kind, gadgets (decoys, storm cloud, tornado, rock pillar, energy wall), hazards (lava geyser, lightning, flare, the 4-car subway train, the highway car, icicles), the ice block, roots, stun stars, the respawn pad, the aim arrowhead and training hitbox volumes.
    - Dino Nuggi's F1 car (`car3D`) is a modelled vehicle: chassis, nose cone, side pods, halo, front and rear wings, and four spinning wheels.
  - **Battle damage:** the lit shader adds object-space scorch patches with ember-glowing rims plus scratched paint. They grow with each fighter's damage percent (`it.dmg`, set in `render/fighter3d.js`).
  - **Rage aura:** from 100% a red fresnel shell and licking flame cones surround the fighter (`rage3D`).
  - **Weather (`render/weather3d.js`):** GPU particle systems made of real geometry, picked per arena (`WX_STAGE`): rain streaks that catch the light, tumbling snow crystals, desert dust lines streaming along the Z axis, embers, ash, petals, leaves, fireflies, bubbles, stardust and confetti.
  - **Text as HTML (`render/fxui.js`):** damage pop-ups, the combo counter, READY / GO! / GAME! banners and off-screen markers are a DOM layer.
  - **3D menus (`render/menu3d.js`):**
    - The main menu floats over a living 3D arena where your fighter and your rival idle.
    - Stage select shows the hovered arena live in 3D.
    - Character select has a 3D showcase: the real model on a pedestal. It spins in on hover, idles through its moves, and celebrates with 3D confetti when picked.
    - The VS nameplates and HUD panels carry live 3D portraits, drawn into transparent windows in the glass UI. Roster tiles and stage cards are 3D renders (`glSnapshot`).
    - The results screen has a 3D victory scene.
  - **Menus restyled:** minimalist glass with cross-fade and glide transitions between screens (the v6 block at the end of `css/style.css`).
  - **36 stage soundtracks (`audio/music.js`):** every arena has its own procedurally composed track, matched to its look. It combines a genre recipe (synthwave, techno/acid, metal, ambient, epic, Japanese, tropical, underwater, music box, desert, forest, haunted, frozen, industrial, EDM, drum & bass, space station, racing, cosmic trance), the stage's own tempo, key and scale, and a lead melody generated from the stage id. Stage select previews the hovered arena's track. The old two-theme sequencer is gone.
  - **The speech announcer was removed.**
- **v7: Ultimates, bespoke idles + punches, expressive 3D faces.**
  - **Ultimates:** every fighter has its own cinematic super move (`data/ultimates.js`). The ULT meter (HUD, under LAUNCH) is hard-earned (`ULT_EARN` in `game/ultimate.js`):
    - **Plain hits give nothing.**
    - **Combos:** only the 3rd hit of a combo onward pays, more for each extra hit (2, 3.5, 5… capped at 8 per hit).
    - **Perfect parries:** +18 each.
    - **Surviving at 120%+:** a slow trickle that speeds up toward 220%, plus +6 every time you ride out a real launch at 120%+.
    - **How rare:** in CPU-vs-CPU play on Hard, about 0.7 Ultimates are fired per 3-stock match (both players together).
    - When the meter is full, **R** (or middle click, or the pink **ULT** button on touch screens) fires it:
    - **Intro:** the world freezes for 46 frames. The camera pushes in, the stage goes dark with a rim light in the fighter's colour, focus lines and an aura build, and a cut-in band shows the move's name. The music is muffled and the phone rumbles.
    - **Approach:** one of ten families: `rush`, `beam`, `meteor`, `quake`, `storm` (bolts / icicles / arrows / holy pillars / data / cannonballs), `vortex`, `uppercut`, `summon` (a tiger, fox, kraken, serpent, dragon, phoenix, spectral horse, bone golem, guardian or mirror legion), `timestop` (a giant clock), and Dino's `grandprix` (F1 laps). Each fighter tunes its family (speed, reach, hits, knockback) and has its own name and three choreography keyframes (`c` charge, `s` strike, `f` finale).
    - **Contact:** the victim is held (`ultHeld`) while the flurry lands, then launched by the finisher. A miss ends in 34 frames of punishable lag. Users and held victims can't be hit; Ultimates are unblockable.
    - **Code:** gameplay is in `game/ultimate.js` (deterministic, so it works online; the button is in the input packet), visuals in `render/ultfx.js` (3D set pieces + canvas fallback), and the CPU fires it when the opponent is in its Ultimate's reach (`ultAIWants`). In Training the meter is always full.
  - **Idle + punch per fighter (`render/motion.js`):** `idlePose` gives each body type its own breathing / fidget code (heavy heave, on-the-toes bounce, all-fours panting, servo twitches, undead sway, grooving…), tuned by the fighter's `MOTION` profile. `punchStyle` chambers, guards and drives the jab string in the fighter's arm style (boxer's straight, haymaker, palm strike, claw rake, piston snap, shield punch…) and keeps the fist on the real hitbox. With the existing walk / run / air / victory / defeat sets, every fighter's Idle, Walk, Run, Punch and Ultimate are unique; the smoke test checks all 80.
  - **3D faces (`eyes3D` in `render/fighter3d.js`):** pupils glide to track the opponent. Hit fighters show cartoon X eyes and an O mouth, dazed ones spinning spirals, winners ^^. Brows scowl while charging (with a bead of sweat), frown while attacking and lift when worried; the mouth grins, grits its teeth or frowns. Visors / masks / beards hide the parts they cover.
  - **Pancake landings:** a fast-fall landing squashes the fighter flat for two frames before it springs back. (Fast-fall itself was clamped to the normal fall speed until now; it now really falls faster.)
  - **iOS:** the Xcode project is landscape-only (`Info.plist`), like Android.
  - **Capes, scarves, tails and hair** (the verlet chains in `stepTrail`, `render/fighters.js`) now whip around in a travelling wave during strikes, specials, Ultimates and launches (`trailWhip`), blow upward during an Ultimate's power-up, and stream in gusting wind on the windswept arenas (`TRAIL_WIND`).
  - **Balance (8 rounds, featured 8, Hard):** Dino Nuggi 88% with Ultimates (87% without), the top tier as intended. Vortex drops from 36% to 26% with Ultimates on: as a zoner it rarely strings 3-hit combos, so it earns little meter.
- **v8: Ultimate fix, post-processing, Retro Challenges.**
  - **Ultimate trigger fix (`ultInput` in `game/ultimate.js`):**
    - **Buffer:** R / middle click / ULT is held for 24 frames, and it fires from idle, running, airborne, the jump squat, behind a shield, or an attack's end-lag. Before, a press only counted on the exact frame the fighter was idle.
    - **Feedback:** pressing it with an uncharged meter says so ("ULT 37%", a buzz, the HUD meter shakes) instead of doing nothing.
    - **Training:** reset moved from R to **T**. R used to reset the fight and fire the Ultimate on the same press.
    - **Touch:** the ULT button is always visible, fills up as the meter charges, and glows when ready.
    - **Tests:** the smoke test drives it through real `keydown` events.
  - **Post FX (`render/postfx.js`, Settings → Post FX):** the main 3D frame renders into an offscreen colour + depth texture, then:
    - **Bloom:** keyed on a glow mask in the target's alpha (additive glows and emissive materials write it), so energy, neon, eyes and lava glow while white or brightly coloured scenery doesn't. It blurs at ½ and ¼ resolution.
    - **SSAO:** normal-aware, at ½ resolution.
    - **Comic ink:** lines wherever depth jumps or creases, on top of bolder inverted-hull outlines.
    - **Halftone:** dots in the shadows.
    - **FXAA:** offscreen targets have no MSAA in WebGL 1, so the composite smooths edges.
    - **Grade:** a saturation and contrast grade.
    - **Modes:** Comic (all of it, the desktop default), Bloom (bloom + ink + FXAA, the phone default), Off (direct rendering with MSAA).
  - **Retro Challenges (`ui/challenges.js`, Main menu → Challenges):**
    - **Classic Arcade:** 6 random rivals at Easy → Extreme on random arenas, then **GIANT OMEGA** on Final Destination. Every fighter has `f.scale`; the boss's is 3, so its hurtbox, attack boxes, shield, stage and platform collision, ledges, model, capes, rage aura and camera framing all scale. It is ~1.9× as heavy and hits 30% harder. A loss offers a continue, and clears are saved.
    - **Break the Targets:** each fighter's own course, seeded by its id. A random walk of platforms out from the start pad keeps every one reachable, and 10 floating 3D bullseyes sit above platforms, up high, in mid-air gaps and under the pad. Attacks (via `HITBOX_LOG`, now logged even with no hittable opponent), projectiles and the Ultimate break them. A speedrun clock runs from GO! and best times are saved per fighter.
- **v9: punch-charged Ultimates, true skin geometry, OMNI HAND, Board the Platforms.**
  - **ULT meter (`ULT_EARN` in `game/ultimate.js`):** it fills only from landed melee hits: 1.8 per punch, +1 for each extra hit in a combo (up to 7 per hit). It never fills passively, and projectiles, parries and damage taken don't count. On Hard, CPU-vs-CPU matches fire about 0.6 Ultimates each, and Dino Nuggi stays top tier (85%).
  - **Skins are geometry (`helmet3D` / `spikedArmor3D` / Void weapons in `render/fighter3d.js`; canvas versions in `drawSkinGear2D`):**
    - **Gold Crusader:** a procedural geometric helmet. There are 5 designs (knight crest, kabuto horns, tech visor and fins, crown-helm spikes, faceted diamond), picked and tuned per fighter, and it replaces clashing headgear (`HELM_REPLACES`).
    - **Void Reaver:** spiked obsidian armour (pauldrons, collar, spine, knuckles, knees) and a different weapon: a jagged void blade, trident, spiked mace, cleaver, kusarigama, crescent bow, or energy claws for unarmed fighters.
    - **Tests:** the smoke test checks that all 7 skins (with the 4 Battle Pass skins of v11) build different 3D models for all 80 fighters.
  - **OMNI HAND (`game/boss.js`):** the Arcade's final boss, after GIANT OMEGA. It's a towering floating cel-shaded glove with 300 HP that takes damage instead of knockback.
    - **Attacks (each telegraphed):** a palm slam (target ring, then floor shockwaves), a finger-poke dash, a ground sweep, a rocket fist and finger-gun shots.
    - **Parry:** a perfect parry staggers it.
    - **Combat hooks:** it occupies the opponent slot with its own `updateHand` brain. `bodyRect`, `launch`, `canBeHit`, `tryGrab`, the renderers and the HUD (which shows HP) all know about it.
  - **Board the Platforms (`ui/challenges.js`):** 10 tiny platforms (36–46 px), placed per fighter by a random walk within jump reach. Land on each before the 45-second clock runs out. Amber beacons mark the platforms still to board; they turn green with a flag once you land. Records are saved, and running out of time ends in TIME UP.
- **v10: smooth tube limbs, touch controls v2, stage progression, punchier SFX.**
  - **Smooth limbs (`render/tubes.js`):** arms and legs are each one continuous tube swept along a quadratic bezier through shoulder → elbow → hand (no ball joints). The curve's control point is pulled toward the joint when a limb folds tight, so punches stay crisp. Tails, capes, scarves, hair and Kraken's tentacles are tubes along a centripetal Catmull-Rom spline. Rings use parallel transport and unit normals, so there is no twisting and the shading is smooth. Meshes come from a pool with static index buffers, refilled with `bufferSubData` each frame (10 sides on phones, 16 on desktop). The sphere mesh is now 56×40 on desktop.
  - **Touch controls v2 (`game/touch.js`):**
    - **Stick:** floating; it appears wherever the left thumb lands. It has a dead zone and a direction arrow, and the base follows a thumb that runs past it.
    - **Buttons:** big buttons in a thumb arc. A touch picks the nearest button centre within 1.6 radii. Sliding onto Jump or Shield works, but sliding between attack buttons doesn't fire them.
    - **Look:** faux-glass buttons (no `backdrop-filter`, which is slow on phones) that glow, scale and ripple when pressed.

## Getting to phones

1. **Touch controls** are done (`www/js/game/touch.js`). On phones and tablets a stick (left thumb: move and aim) and Attack / Smash / Special / Jump / Shield buttons (right thumb) appear during a match. Settings → Touch controls can force them On or Off. To try them on PC, set it to On and use a touchscreen, or Chrome DevTools' device mode.
2. **Android:** install [Android Studio](https://developer.android.com/studio), run `npm run android`, then press Run. Publishing on Google Play needs a developer account ($25 one-time fee).
3. **iOS:** Apple only lets you build iOS apps on a Mac with Xcode. Copy this folder to a Mac, run `npm install`, then `npm run ios`. The App Store needs an Apple Developer account ($99/year).
